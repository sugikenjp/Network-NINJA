# Network-NINJA

**ルーティングを活用して、未使用ネットワークを分散型セキュリティセンサーへ。**

Network-NINJAは、未使用のネットワークアドレス空間をアクティブな監視領域として活用し、不審なネットワーク活動を検知するためのオープンソースのネットワークセキュリティツールです。

ネットワーク内に多数のデコイシステムを配置する代わりに、Network-NINJAはルーティングを利用して、実在しそうでありながら実際には使用されていないネットワークレンジ宛ての通信を、指定された **Trap Zone** へ誘導します。

通常、正規のユーザーやシステムが未使用のネットワークレンジへ通信する理由はありません。そのため、Trap Zoneへ到達する通信は、ネットワーク偵察、スキャン、設定ミス、不審なラテラルムーブメントなどを識別するための有用なシグナルとなる可能性があります。

Network-NINJAは、この仕組みを分散したネットワーク環境でも管理できるようにすることを目的としています。

---

## なぜNetwork-NINJAなのか？

従来のネットワーク監視では、主に既知のシステムやサービスに関係する通信を監視します。

しかし、ネットワーク内の未使用領域も重要なセキュリティシグナルとして活用できます。

例えば、攻撃者がネットワーク偵察を実行している状況を考えてみます。

```text
10.10.1.10   Production Server
10.10.1.20   Production Server
10.10.1.30   Production Server

10.20.0.0/16  Unused Network
```

`10.20.0.0/16` へアクセスする正当な理由が存在しない場合、このネットワークへの通信は調査する価値のあるイベントと考えることができます。

Network-NINJAはルーティングを使用して、そのような通信を制御されたTrap Zoneへ転送し、観測・分析できるようにします。

```text
                       通常通信
                          |
                          v
                    Production Network
                          |
           +--------------+--------------+
           |                             |
           v                             v
    Production Systems            Unused Networks
                                         |
                                    Routing
                                         |
                                         v
                                    Trap Zone
                                         |
                                         v
                                Security Monitoring
```

これにより、未使用のネットワーク空間そのものをセキュリティ監視アーキテクチャの一部として活用できます。

---

## コンセプト

Network-NINJAの基本的な考え方はシンプルです。

> **誰も通信する必要のない未使用ネットワークに通信が発生したのであれば、その通信には注目する価値がある。**

Network-NINJAは、以下の要素を組み合わせます。

- ネットワークルーティング
- 未使用のネットワークアドレス空間
- Trap Zone
- 分散監視
- 集中管理

これらを組み合わせることで、想定外のネットワーク通信を検知するための仕組みを提供します。

Trap Zoneは、実際の本番ネットワークを再現する必要はありません。

代わりに、実在しそうな未使用のネットワークレンジを検知ポイントとして活用できます。

ネットワーク偵察やスキャンがこれらのアドレスレンジへ到達すると、ルーティングによって通信を監視基盤へ誘導できます。

---

## アーキテクチャ

Network-NINJAは、主に **Manager** と **Agent** から構成される分散アーキテクチャを採用しています。

```text
                    +-----------------------+
                    | Network-NINJA Manager |
                    +-----------+-----------+
                                |
                       設定 / 集中管理
                                |
             +------------------+------------------+
             |                                     |
             v                                     v
      +-------------+                       +-------------+
      |   Agent A   |                       |   Agent B   |
      +------+------+                       +------+------+
             |                                     |
          Routing                                Routing
             |                                     |
             v                                     v
      +-------------+                       +-------------+
      |  Trap Zone  |                       |  Trap Zone  |
      +-------------+                       +-------------+
```

このアーキテクチャにより、複数のネットワーク拠点へTrap Zoneを分散配置しながら、集中管理と可視性を維持することを目的としています。

---

## 主要コンポーネント

### Manager

Managerは、Network-NINJA環境を集中管理するためのコンポーネントです。

Network-NINJA Agentを管理し、分散した環境を一元的に管理するための中心的な役割を担います。

### Agent

Agentは、Network-NINJAの機能が必要となるネットワーク拠点で動作します。

周辺のネットワーク環境と連携し、対象となる通信を適切なTrap Zoneへ誘導します。

### Trap Zone

Trap Zoneは、監視対象となる未使用ネットワークレンジ宛ての通信を受け取るための制御された領域です。

Trap Zoneへ到達した通信は、セキュリティ監視システムや検知システムによって観測できます。

---

## 動作の仕組み

一般的なNetwork-NINJAの構成では、以下のような流れになります。

```text
1. 実在しそうな未使用ネットワークレンジを定義
                    |
                    v
2. Network-NINJA環境へ向けたルーティングを設定
                    |
                    v
3. ホストが未使用ネットワークへスキャンまたはアクセス
                    |
                    v
4. 通信が設定されたルートを通過
                    |
                    v
5. 通信がTrap Zoneへ到達
                    |
                    v
6. セキュリティ監視システムが通信を観測
```

例えば、以下のような構成です。

```text
攻撃者 / 侵害されたホスト
          |
          | Network Scan
          v
+---------------------+
| Enterprise Network  |
+----------+----------+
           |
           | 未使用ネットワークへのRoute
           v
+---------------------+
| Network-NINJA Agent |
+----------+----------+
           |
           v
+---------------------+
|      Trap Zone      |
+----------+----------+
           |
           v
+---------------------+
| Security Monitoring |
+---------------------+
```

このアプローチによって、本来は正規の通信が存在しないはずのアドレス空間を、検知インフラの一部として利用できます。

## 想定ユースケース

### ネットワーク偵察の検知

正規のシステムが存在しないはずのネットワークレンジに対するホストやサービスの探索を検知します。

### 内部ネットワークスキャンの検知

未使用または想定外のネットワークセグメントへ通信しているホストを識別します。

### ラテラルムーブメントの可視化

侵害されたホストが、通常の通信範囲を超えてネットワークを探索した際の追加の検知シグナルとして活用します。

### 分散型Trap Network

大規模または複数セグメントに分かれたネットワーク環境に複数のTrap Zoneを配置し、それらを集中管理します。

### セキュリティ研究

ルーティングを活用したネットワークデセプションおよび検知技術の検証に利用します。

---

## なぜルーティングなのか？

多くのデセプション技術では、個別のデコイホストやサービスを配置します。

Network-NINJAでは異なるアプローチを採用します。

> **ネットワークそのものを検知メカニズムの一部として利用する。**

ルーティングを利用することで、すべての宛先IPアドレスに実際のシステムを配置することなく、特定のアドレスレンジへの通信をセキュリティ監視基盤へ転送できます。

概念的には次のようになります。

```text
従来のアプローチ

Attacker
   |
   +----> Honeypot A
   +----> Honeypot B
   +----> Honeypot C


Network-NINJAのアプローチ

Attacker
   |
   +----> Unused Network Range
                     |
                  Routing
                     |
                     v
                 Trap Zone
```

これにより、ルーティングレイヤーを活用したネットワークデセプションを構成できます。

## 利用例

例えば、以下のネットワークを使用している企業環境を想定します。

```text
10.10.0.0/16   Production
10.20.0.0/16   Production
10.30.0.0/16   Production
```

さらに、実在しそうでありながら、実際には使用していないネットワークレンジを定義します。

```text
10.99.0.0/16   Trap Network
```

通常、エンドポイントが `10.99.0.0/16` へ通信する理由はありません。

侵害された端末が広範囲のネットワーク偵察を開始したとします。

```text
10.10.x.x
10.20.x.x
10.30.x.x
10.40.x.x
...
10.99.x.x
```

Trap Networkへの通信をNetwork-NINJAのTrap Zoneへ誘導することで、その通信を検知する機会を作ることができます。

これにより、対象のアドレスレンジ全体へ実際の本番ホストを配置することなく、追加の検知ポイントとして活用できます。

## セキュリティ上の考慮事項

Network-NINJAは、特定のネットワーク通信のルーティングや監視方法を変更します。

そのため、本番ネットワークへ導入する前に、管理されたテスト環境で動作を検証してください。

意図しない通信の転送を防ぐため、ルーティング設定、監視対象アドレスレンジ、Trap Zoneの配置を慎重に確認する必要があります。
